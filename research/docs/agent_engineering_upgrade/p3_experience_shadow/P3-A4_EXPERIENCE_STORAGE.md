# P3-A4 isolated relational storage and governance

ExperienceRepository reuses the project's SQLAlchemy async engine/session factory, but owns independent transactions and a separate ExperienceBase. The original business Base, startup schema and Alembic history are unchanged. Explicit initialization accepts only isolated SQLite and refuses any database containing non-experience tables. No production database URL is loaded or migrated. Three tables hold generic candidate records, versioned governance events and content-free deletion tombstones.

Records persist a validated schema payload, tenant/user/session opaque refs, content/source-version fingerprint and optimistic version. Every read/list/write/review/delete requires a verified offline identity and exact three-part scope; it is not sufficient to pass public user_id. No cross-tenant, cross-user or cross-session recall exists. No public production authentication channel is added. Source artifact refs remain private; generic lessons are not automatically shared.

Lifecycle: PROPOSED→NEEDS_REVIEW→VERIFIED_OFFLINE or REJECTED; current records may be invalidated to EXPIRED. REJECTED/EXPIRED cannot be reactivated or automatically renewed. Verification requires a hash-resolved offline applicability report bound to family, source version, candidate fingerprint, independent labels, at least3cases, passing outcome and zero safety conflicts. These metadata checks authenticate an immutable local report, not independent truth by themselves; A5's independent author/actual results provide that evidence. VERIFIED_OFFLINE is bounded test evidence, never approval for production use.

Review status is separate. The prototype may record MODEL_REVIEWED, but has no authenticated human approval channel and rejects attempts to fabricate HUMAN_APPROVED. Human annotation stays NOT_RUN in this phase. ACTIVE is absent from settings and lifecycle. Initial insertion also refuses pre-approved or pre-verified payloads. Equal fingerprints in the same private scope deduplicate without extending TTL or approving another source.

Candidate ingress revalidates the exact reviewed generic lesson catalog, all conditions, UTC timestamps and provenance. No raw chat, model reasoning or tool values are persisted. Known personal/secret/order/SKU identifiers in source references are rejected pending replacement by opaque provenance; malicious/free-text lessons are rejected rather than inserted. This constrained offline catalog is a stronger boundary than relying on broad free-text PII regexes alone. It is not a universal PII detector for arbitrary future input formats.

Deletion physically removes the candidate payload and associated governance events. A tombstone keeps only scoped opaque identifiers, the generic-content fingerprint and deletion time to prevent automatic reimport; it contains no lesson, transcript or original user value. Lazy expiry is checked on reads/lists and duplicate insertions, never using old business state as fresh evidence. Compare-and-swap updates reject stale versions; a failed event insert rolls back the whole independent experience transaction.

Validation: initial missing-storage RED retained;17SQLite integration tests pass, including file-backed persistence across instances, dedup, all scope boundaries, unverified identities, test-versus-review separation, version conflicts, rejection, expiration, physical deletion/tombstone, privacy/injection rejection and transaction fault rollback. Isolated schema upgrade/drop and reinitialization are explicit. PostgreSQL CREATE TABLE statements for all three tables compile with its actual SQLAlchemy dialect. **Live PostgreSQL migration/concurrency is NOT_RUN**; no production compatibility or deployment claim is made.

Rollback: stop the offline runner (mode defaultoff), export non-sensitive governance metadata if required, then call drop_schema only on the dedicated isolated SQLite engine with isolated=True. It drops only ExperienceBase tables, never the business Base. Retain/delete local backups according to the operator's policy; this prototype creates no automatic backup or external cache. Redis and Qdrant are not used.
