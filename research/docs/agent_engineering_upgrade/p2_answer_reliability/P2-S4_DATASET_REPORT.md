# P2-S4 answer-quality datasets

Development:24 independent scenarios,40 turns,45 annotated facts. Independent Holdout:30scenarios,41turns,46facts. Counts exceed20minimum without merely changing IDs. Domains include multi-goal order header/logistics/items, target changes/history, fresh state events, SKU inventory/price/detail/warranty, refund observation, negative/conditional operations, pending/confirmed/rejected cancellation, Owner hiding, general/mixed policy, cross-session clarification, greetings and long-window continuity.

Scenario files use unchanged agent-scenarios-v2.1. Separate per-turn AnswerGold files list subgoals, required facts and actual tool/retrieval requirements, legal phrase variants, prohibited claims, expected abstention and semantic scope. Static policy/Owner/free clarification/human-quality judgments without adequate deterministic evidence stay NOT_ASSESSED; Development21turns and Holdout14turns require open semantic assessment. No human annotator calibration has occurred (NOT_RUN). Independent author review is not relabeled human review.

The Holdout author received only public fixture/tool/schema contracts and no product implementation, development data or historical failures. Concrete inputs/Gold/results were withheld from implementer until source/evaluator freeze; only aggregate schema/encoding/hash gates were visible. The author checked each annotated fact against AST-extracted synthetic seed plus public tool output contracts. This is procedural process isolation, not cryptographic protection. After final evaluation it becomes regression data, never a future fresh blind set.

Quality gate: strict UTF-8/no U+FFFD/punctuation-only corruption; valid roles/turn schema; per-turn answer annotation counts; unique IDs and goal references; compiled regex without wildcard-only extra erasure; zero full-scenario and terminal-task exact overlap between splits. Public write/owner contracts were reconciled before freeze: external state changes are explicitly allowed fixture mutations, no Agent audit unless actual confirmed write; Owner lookup is business_rejected with no private output. Generated tool IDs and retrieval ordering are not overconstrained.

Before any dataset execution, Development draft quality review split order status and monetary obligations into separate goal names while keeping the same required facts/values/tools; unfrozen draft is retained. Optional observed extra facts were added to the new evaluator contract with RED2→GREEN22 tests: they never count as required subgoals but still require actual support when stated. This does not alter old Gold or treat unasked facts as completed tasks. The independently frozen Holdout annotations were not changed. Freeze records exact final scorer/data SHA, rather than silently mixing annotation versions.

Four separate answer-only counterexamples distinguish complete, omitted amount, false operation and unsupported promise with identical actual observations; they are scorer calibration fixtures, not Agent/LLM runs. Judge/Generate failures, length, malformed/schema output and stream interruption are covered by separate S1/S2 test/replay matrices. Current scenario driver has no tool-fault injection field; no simulated tool-failure scenario is falsely described as a natural Agent run. Faults are evaluated separately under the same source controls in S5.

No new paid API request. Historical P2/P2-Q/P2-R datasets, Gold, task states and runs remain unchanged. The P2-S new-answer scorer is an additional evaluation view; historical scores are not rewritten. Exact SHA256/counts are in evidence/s4_dataset_quality.json, datasets/holdout_manifest.json and evidence/candidate_freeze.json. Holdout agent execution remains NOT_RUN at this checkpoint; source and evaluator freeze precedes S5/S6 evaluation.
