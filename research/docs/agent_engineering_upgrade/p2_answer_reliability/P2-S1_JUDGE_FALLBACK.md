# P2-S1 Judge and fallback reliability

Baseline path: Generate JSON answer → FaithfulnessChecker (512output cap) → parsed verdict. Its old prompt duplicates status/supported and requests unbounded rationale/spans. Provider rejects finish_reason=length before parsing; Checker collapses output errors and catches provider exceptions. Judge errors then call _offline_answer, whose configuration message and latest-single-tool/first-chunk behavior explains B31 and dv06. Six historical Judge truncations are actual provider responses; a finite output budget plus expansive schema is observed, but public traces cannot independently establish hidden backend token allocation. No claim that increasing budget alone fixes reliability.

Change: keep512default and all five status semantics; prompt asks only compact status, optional at most two short unsupported spans, no rationale. Existing stored status/supported shape and strict legacy boolean verdict remain compatible. Checker records TRUNCATED, MALFORMED_JSON, SCHEMA_ERROR, API_ERROR separately; syntactically valid wrong fields are INVALID_OUTPUT/SCHEMA_ERROR. Judge cannot declare an infrastructure verdict. No automatic Judge retry. The original answer is neither declared supported nor hallucinated on Judge error.

Generate failure preserves API/output/truncation category. A pure deterministic renderer uses allowlisted fields from successful nontruncated business-tool outputs, collects all known facts rather than just the last tool, and states remaining limits. It never quotes arbitrary retrieved snippets during real failure or invents missing-key explanations. Cancellation requires status=cancelled; requested refunds/returns are applications, not settled payments. A later write invalidates earlier same-order read facts for fallback. No SQL/tool invocation occurs in this renderer. Existing pending-action/Owner/clarification branches remain authoritative.

Only truly unsupported answers enter bounded self-correction. An unverified rewrite no longer triggers an additional Judge request for an arbitrary extractive fallback. The final safe fallback retains the unknown/insufficient verdict; it is not auto-PASS. For unsupported rewrite failure, actual business evidence can still be conveyed with explicit limits.

Provider streaming now rejects length termination and EOF without a terminal marker rather than silently accepting a partial answer. Existing ChatService SSE emits only final validated text after graph completion; iterator/ASGI disconnect cleanup tests remain passing. Provider normal structured path, no-paid truncation retry and original actual-model metadata behavior remain compatible.
