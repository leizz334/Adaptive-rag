# 工程难点与证据

## 1. 从“模型说执行”到真实业务终态

Planner输出受工具schema和已验证skill约束，原执行器检查Owner/HITL。取消订单要先提案、再确认；PostgreSQL持久pending行与业务幂等记录在事务/行锁下处理，重放复用同一Action。通过工具返回、SQL终态与审计数判断执行，不能用最终回答代替写入证据。当前演示取消审计1条见r2_business.json。

## 2. 私有RAG隔离覆盖完整链路

P4-F解决的不只是向量过滤：入库与chunk元数据、BM25/Qdrant/Hybrid、重排后输出/引用、Redis检索缓存、更新/删除/重索引都绑定认证主体与有效版本。客户端tenant/user字段不能授权。真实浏览器展示A入库/检索/引用，B的列表、检索、删除和Trace访问均无A资料。

## 3. Redis故障下明确拒绝

敏感/可能付费操作采用Redis原子共享配额，故障503，不能用进程内计数冒充分布式限流。历史真实集成包含Redis断开/超时/恢复及多进程配额验证，本阶段全量再次回归；根API-only旧Compose缺Redis时应安全拒绝，不能为演示改回fail-open。

## 4. 异步SSE与身份生命周期

SSE先报告真实节点，回答校验/持久化后才分块发送，避免把未校验模型JSON展示为最终答案。前端统一HTTP/SSE错误，Headers后超时也警告结果可能已提交，不自动重放。所有身份请求绑定AbortController；A的迟到401不能清除B的新凭证。错误和取消路径有单元及真实浏览器断网证据。

## 5. 可解释界面与数据最小化

Trace仅展示实际span/计划/工具有限结果、来源片段、Memory元信息。以服务端生成root绑定Owner/session，客户端x-trace-id只作关联。原始Prompt/State/summary/凭据不导出。15分钟单进程快照是明确工程边界，不包装成完整可观测平台。历史文本恢复不能伪造旧Trace、citation或Action。

## 6. 评测与结论可追溯

P4-C/D和S1-EX真实DeepSeek实验保留冻结Gold/评分器/源码/模型配置、逐请求账本/usage/延迟/上界费用；未知请求不重试。自动工具/业务代理、字段检查和完整人工语义质量分别报告。S1-EX三臂没有建立成功率收益，观察到1个字段负向变化也未作因果归因；人工审核仍未完成。Web阶段修复字段coverage/fallback后不改写旧成绩。

## 7. 可恢复的交付过程

feature-list/progress/Git三方核对，任务测试后checkpoint。新run独占新资源、init拒绝旧目录，stop验证进程启动时间/命令/cwd/UID和Docker标签，保留卷。代理继承导致的启动失败保留RED，修复仅影响子进程。所有结果有实际命令/证据，不把截图、Mock或历史PASS冒充当前完整验收。

## 后续 S2 技术学习建议（未启动）

1. **事务与异步可靠性**：围绕本项目confirmation行锁/幂等指纹、SSE取消前后提交边界做独立学习实验，练习解释at-least-once请求与业务单次效果的区别。
2. **评测方法**：学习独立人工标签、语义评分校准、配对统计与样本量；从已有NOT_ASSESSED和极小样本限制出发，区分检索指标与业务收益。
3. **生产边界**：学习可信身份供应商/TLS/凭证轮换、数据库迁移与备份、Owner感知的持久Trace及历史分页；先写验收和故障模型，再评估是否需要扩展。

这些是基于现有实现与未完成条件的学习方向，不是本阶段新增功能或自动执行计划。
