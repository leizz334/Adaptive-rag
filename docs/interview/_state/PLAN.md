# 360 题答案库文档计划

2026-11-16。仅文档；复用固定工作树和新文档分支，不重复项目初始化。

## 结构与口径

- 原题来自根目录用户提供的题库，360 个原编号、20 个专题、130 个★；原文件保持未跟踪状态，不改写、不擅自加入 Commit。
- `questions.json` 固定原题、SHA256、编号、专题、来源行、60 核心题及唯一目标文件。八份答案文件各负责独立编号集合，模拟面试只引用编号，不复制长答案。
- 每题使用 `### Q001：原题` 和固定五节：标准答案、面试口述版、Adaptive-RAG实际实现、面试官可能追问、测试与证据。至少两组具体问答；口述版优先解释机制、取舍和失败边界。
- 源码链接用相对路径和 `#L行号`；项目事实以本次基准提交源码为准。未实现、未验证、单元/Offline/MockTransport/真实 DeepSeek/NOT_RUN 分开标注。
- 不把旧研究指标、947 项历史 pytest、54 项前端测试或20次真实调用当作本轮重跑。真实 HITL 仍 NOT_RUN。人的独立贡献、真实用户数和线上 SLA 无证据，不虚构。
- 原有三章与旧逐题资料保留，仅在 README 加新版入口。

## 四批交付

1. B1：先写 manifest 指定的60道核心题，跨八份目标文档；验证精确编号、原题文字、五节、追问、源码/测试链接和引用行，再提交。
2. B2：补齐其余 Agent、RAG、Tool/MCP/Memory/HITL、Prompt、评测、LLM/多 Agent 题；同样验证后提交。
3. B3：补齐 Python/FastAPI、数据库/Redis/Docker、系统设计/手写题；示例明确教学用途，代码进行语法及适当纯函数检查，不启动服务。
4. B4：补齐项目专项、连续追问模拟、14天路线、全360索引和未实现/缺证据清单。
5. B5：全量覆盖/去重/结构/链接/代码位置核验、语义抽查、保护检查，文档 Commit 和普通 Push，并核验远端 HEAD。

## 分工边界

- Agent/LangGraph 与 Tool/Memory/HITL 两份文档独立撰写。
- RAG 与 Prompt/评测/成本/LLM 两份文档独立撰写。
- Python/FastAPI 与 DB/Redis/Docker 两份文档独立撰写。
- 主任务负责项目、系统设计/代码、模拟、路线与全量校验。分工只写各自文档；所有 Git 和状态变更由主任务执行。
- 第一批完成后才能释放第二批写作；后续同理。独立资料阅读和源码核对可以提前，不越批写答案。

## 验证

`validate.py` 校验原题哈希、各题唯一归属/原文、结构、追问数、锚点、相对链接及行号；生成批次/全量核验记录。AST 符号索引供交叉核验，脚本不导入业务模块。文档示例不自动运行数据库/HTTP/模型。

保留输入、非面试文档跟踪文件哈希、原旧面试资料和 Stash 基准。交付只允许 `docs/interview/` 及其恢复资料变更，不修改业务代码、Docker、数据库、`.env` 或实验。
