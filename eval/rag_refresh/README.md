# RAG 专项复测

## 样本与评分

复测的业务源码为 `07057f0676e3644ff4838c61abe59962556a8cd8`。测试集为 [rag_eval.jsonl](../dataset/rag_eval.jsonl)，含 65 条不同的政策问题。它也是原独立生成评测器的输入，冻结内容可追溯至初始提交 `516efa0`。60 条标注了一篇相关文档，5 条标注了两篇，分别为 `r002`、`r025`、`r026`、`r034`、`r065`。39 篇政策文件的 SHA-256 均与发布版历史清单一致，70 个文档标签均可解析到仓库政策。测试集 SHA-256 为 `2de6a3676428d57ecc45379889f4e79403a343711ba93bca11dda2d05534a3d9`。仓库保存了既有 Gold 标签和答案关键词，标注过程未留单独的审阅记录。

检索按文档文件名去后缀并去重，保留首次出现顺序。P@1 是首文档相关的比例。Recall@3 先逐题计算前三文档命中的 Gold 占比，再对 65 题取平均。Hit@k 统计前 k 中至少命中一篇 Gold 的题数比例。MRR 对第一篇相关文档的位置取倒数，未命中记零。可替代文档可能含有正确政策，但仍按冻结标签评分。例如 `r009` 标注 `faq`，历史排名中更靠前的 `handoff_hours` 也含该时段。此类差异单独解释。

生成沿用 [原始 RAG 评测器](../rerank_ablation.py) 的 A 组。以 Gold 文档数量选择 SINGLE 或 MULTI 的评测入口，分别统计入口及实际发生的轮数。自然组由 Self-RAG 自己决定停止，强制组只对同样五个多文档问题运行两轮控制。事实覆盖采用问题级双条件，原参考答案裁判判对，且检索片段覆盖问题全部条件。单列判对、检索证据充足性和字面关键词全命中率。忠实度与幻觉率的分母为得到确定裁决的回答，单列证据不足、裁决错误、评审覆盖率及样本数。同一模型系列承担生成与评审，结果有评审偏差。

## 当前发布源码的四路隔离检索

每组使用相同的 65 条原始查询、索引和候选块深度 8。混合检索用 RRF 合并 BM25 和本地向量。Cross-Encoder 只重排混合检索的同一批块。这部分无生成调用。

| 检索方式 | P@1 / Hit@1 | Recall@3 | Hit@3 | Hit@5 | Hit@8 | MRR |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| BM25 | 80.00% | 90.00% | 90.77% | 96.92% | 96.92% | 0.8556 |
| 向量 | 81.54% | 94.62% | 95.38% | 98.46% | 100.00% | 0.8846 |
| 混合 | 83.08% | 93.08% | 93.85% | 96.92% | 98.46% | 0.8915 |
| 混合 + Cross-Encoder | **89.23%** | **96.15%** | **96.92%** | 98.46% | 98.46% | **0.9321** |

Cross-Encoder 让首位命中从 54/65 增至 58/65，8 题改善、4 题退化。`r021` 的保修条款从第 5 名升到第 1 名，`r027` 的优惠券条款从第 4 名升到第 3 名。`r009` 的 Gold 文档在混合候选中缺席，精排只能调整已经召回的证据。沿用 11 月 22 日归档的深度口径可复现该归档四组在已发布精度下的指标。 [逐题排名](evidence/ranking/cases.jsonl) · [汇总与历史深度视图](evidence/ranking/summary.json)

## 真实生成与自然停止

自然组 65 题均只执行一轮，含进入 MULTI 路径的 5 题。重新运行的 P@1 89.23%、Recall@3 94.62%、Hit@3 95.38% 和 MRR 0.9231 与历史自然组一致，55/65 的候选完整顺序和实际上下文也一致。自然组包含真实查询改写以及单双检索入口，隔离检索统一直接使用原问句及八个候选块，两个协议的 Recall@3 分别为 94.62% 和 96.15%。

当前自然组原参考裁判判对 65/65，关键词全命中 64/65。双条件事实覆盖 64/65，历史自然组为 62/65。忠实度从历史的 63/64 到本次 65/65。历史有 1 条不支持、1 条证据不足，当前评审对 65 条都给出支持。自然组结果包含合理告知用户证据缺口，不能把全部判对解释为每题都有完整的政策信息。

`r011` 的旧答复把「拆封但未激活」直接套用了未拆封政策，新答复使用政策原本写明的「拆封激活」条件。两次 `r023` 都说明现有证据未给出 NEW10 门槛，旧忠实度裁判标为证据不足，新裁判标为支持，当前仍判该题的事实证据覆盖不全。该例显示评分随裁决口径而波动。 [自然组原始记录](evidence/generation/natural/A.jsonl)

## 复现

现有 `adaptive-rag` 环境需提供 `.[rerank]`、`.[docs]`，以及这两个模型的本地目录。使用 Hugging Face 的对应修订下载。第一次生成评测会计费，额度由 [计量边界](../release/shared/budget.py) 逐请求控制。

| 本地模型 | 固定修订 |
| --- | --- |
| `BAAI/bge-small-zh-v1.5` | `7999e1d3359715c523056ef9478215996d62a620` |
| `BAAI/bge-reranker-base` | `2cfc18c9415c912f9d8155881c133215df768a70` |

```bash
python -m eval.rag_refresh.ranking --embedding-model "$BGE_EMBEDDING" --reranker-model "$BGE_RERANKER" --output data/local/rag-ranking
python -m eval.rag_refresh.live --check-budget
python -m eval.rag_refresh.live --embedding "$BGE_EMBEDDING" --reranker "$BGE_RERANKER" --output data/local/rag-generation
python -m eval.rag_refresh.analyze data/local/rag-generation
```

密钥可由进程环境变量 `DEEPSEEK_API_KEY` 提供，或用 `--env-file` 从受保护文件读取该键。请使用新输出目录。脚本对官方 DeepSeek 端点做模型和人民币余额检查，累计上限 ¥0.60 和 420 次请求，禁用思考和自动重试。

已保存的证据可直接无密钥复算。

```bash
python -m eval.rag_refresh.ranking --verify --output eval/rag_refresh/evidence/ranking
python -m eval.rag_refresh.analyze eval/rag_refresh/evidence/generation --verify
```
